## 核心能力

- ✅ **智能识别**：自动识别过短章节和扩展点
- ✅ **内容扩充**：基于文献深度扩充，不编造
- ✅ **图表增强**：增加框架图、流程图、对比表
- ✅ **文献凝练**：阅读原文并融入核心观点
- ✅ **质量保障**：扩展后自检，确保逻辑连贯

## 工作流程

### Phase 1: 分析诊断（10min）

**目标**: 识别初稿中的扩展机会点

**步骤**:
1. 统计各章节字数
2. 识别 <500 字的末级标题
3. 识别连续单句换行段落
4. 分析当前图表数量和分布
5. 评估参考文献利用程度

**输出**: `expansion_plan.md`

```markdown
# 扩展计划

## 章节分析
| 章节 | 当前字数 | 状态 | 扩展策略 |
|------|----------|------|----------|
| 3.1.1 | 320 | ⚠️ 过短 | 增加方法细节 |
| 4.2.3 | 180 | ⚠️ 过短 | 增加案例分析 |

## 图表规划
- [ ] 增加系统架构图（第2章）
- [ ] 增加算法对比表（第4章）

## 文献利用
- [ ] 阅读 [15][23][31] 并融入正文
```

### Phase 2: 内容扩充（核心，主代理亲自完成）

**目标**: 基于文献和领域知识扩充内容

**核心原则**:
1. **主代理亲自撰写**：绝不委托子代理
2. **基于文献扩充**：每个扩充点必须有文献支撑
3. **维持框架**：不删除现有子标题，不增加新标题
4. **服务论点**：扩充内容必须支撑章节核心论点

**扩充策略**（按优先级）：

#### 策略1: 深度阐述（优先）
- 将概括性陈述展开为详细论述
- 增加方法的技术细节
- 补充实验设置和结果分析

#### 策略2: 案例分析
- 增加具体应用案例
- 详细描述实验场景
- 分析结果的实际意义

#### 策略3: 对比讨论
- 增加方法间的对比分析
- 讨论不同方案的适用场景
- 分析优缺点和权衡

#### 策略4: 文献综述
- 凝练参考文献核心内容
- 增加对重要工作的讨论
- 补充相关研究的演进脉络

#### 策略5: 局限性补充（新增，强制）
- **识别目标**：找出初稿中仅有优势描述而无局限性分析的方法段落
- **补充内容**：为每个方法补充**四段式完整分析**：
  1. **原理**：方法的技术原理（基于文献）
  2. **优势**：为什么有效，附具体数据或结论（基于文献）
  3. **局限性**：方法的不足、已知问题、适用边界（必须基于文献）
  4. **适用场景**：该方法最适合什么任务、什么条件下有效
- **检查标准**：扩充后的段落必须包含完整的四段式分析
- **禁止行为**：不只写优势不写局限

**扩充标准**:
- 末级标题内容 ≥ 500 字
- 单句段落扩展至 ≥ 100 字
- 每个扩充点添加交叉引用
- **每个方法必须包含四段式完整分析（原理→优势→局限→适用场景）**

### Phase 3: 图表增强（30min）

**目标**: 增加高质量图表，提升可视化效果

**图表类型**（按优先级）：

| 优先级 | 图表类型 | 适用章节 | 占比限制 |
|--------|----------|----------|----------|
| 1 | 方法框架图 | 方法论章节 | ≤30% |
| 2 | 算法流程图 | 方法论章节 | ≤30% |
| 3 | 对比表格 | 实验/对比章节 | ≤30% |
| 4 | 伪代码 | 方法论章节 | ≤30% |
| 5 | 系统架构图 | 引言/背景章节 | ≤30% |

**图表规范**:
- 使用 TikZ 绘制（遵循 latex-flowchart 技能）
- 每个图表必须有明确图注
- 图表内容必须与正文一致
- 图表总页数 ≤ 总页数 30%

### Phase 4: 文献完善（20min）

**目标**: 补充文献标识信息，增强可验证性

**操作规范**:
1. **补充 DOI**：优先为每条文献添加 DOI 链接
2. **补充 arXiv**：对预印本论文添加 arXiv 链接
3. **验证链接**：确保链接格式正确且可访问
4. **避免强补**：不强行补充无稳定 URL 的文献

### Phase 5: 质量检查（15min）

**目标**: 确保扩展后的论文质量达标

**6维度检查**:

| 维度 | 检查项 | 标准 |
|------|--------|------|
| 结构 | 框架完整性 | 未删除原有子标题 |
| 内容 | 扩充质量 | 末级标题 ≥500 字 |
| 逻辑 | 连贯性 | 无矛盾，过渡自然 |
| 图表 | 可视化 | 图表占比 ≤30% |
| 引用 | 交叉引用 | 所有扩充点有引用支撑 |
| 规范 | 格式 | 符合 LaTeX 规范 |

**自检问题**:
1. 扩展内容是否支撑章节主题？
2. 与原文风格是否一致？
3. 是否有重复或矛盾的内容？
4. 图形图注是否清晰？
5. 交叉引用是否正确？
6. 总页数是否达标？
7. 图形占比是否超过 30%？

## 扩展方法详解

### 方法1: 识别并扩充过短章节

**识别规则**：
```python
def analyze_sections(latex_text):
    sections = get_section_content(latex_text)
    expansion_points = []
    for s in sections:
        if s['level'] == 'subsubsection' and s['chars'] < 500:
            expansion_points.append({
                'section': s['title'],
                'current_chars': s['chars'],
                'target_chars': 500,
                'strategy': 'depth_elaboration'
            })
        # 检测连续单句换行
        if has_single_sentence_paragraphs(s['content']):
            expansion_points.append({
                'type': 'single_sentence',
                'paragraphs': get_single_sentence_paragraphs(s['content']),
                'target_chars': 100
            })
    return expansion_points
```

**扩充策略**：

| 场景 | 扩充方法 | 示例 |
|------|----------|------|
| 方法描述过短 | 增加技术细节、公式推导 | 补充算法步骤的数学描述 |
| 实验分析过短 | 增加案例分析、结果讨论 | 详细描述实验场景和结果意义 |
| 对比讨论过短 | 增加多维度对比、适用场景 | 讨论不同方法的优缺点 |
| 背景介绍过短 | 增加文献综述、演进脉络 | 梳理相关研究的发展历史 |

### 方法2: 增加图形元素

**框架图**（展示方法论框架）：
```latex
\begin{figure}[htbp]
\centering
\input{figures/framework.tex}
\caption{XX方法整体框架。该框架包含三个核心模块：...}
\label{fig:framework}
\end{figure}
```

**流程图**（展示算法流程）：
```latex
\begin{figure}[htbp]
\centering
\input{figures/algorithm_flow.tex}
\caption{XX算法执行流程。步骤1：...；步骤2：...}
\label{fig:algorithm}
\end{figure}
```

**对比表**（展示方法/结果对比）：
```latex
\begin{table}[htbp]
\centering
\caption{不同XX方法的性能对比}
\label{tab:comparison}
\begin{tabular}{lccc}
\toprule
方法 & 指标A & 指标B & 指标C \\
\midrule
方法1 & 0.85 & 0.92 & 0.78 \\
方法2 & 0.88 & 0.89 & 0.82 \\
\bottomrule
\end{tabular}
\end{table}
```

### 方法3: 凝练参考文献内容

**操作步骤**：
1. 通过 DOI/arXiv 链接获取原文
2. 阅读摘要、引言、方法、实验部分
3. 提取核心方法、主要贡献、重要数据
4. 用自己的语言转述并融入正文
5. 添加交叉引用 `\cite{key}`

**凝练模板**：
```
Smith等人~\cite{smith2020} 提出了一种基于XX的方法，
该方法通过XX技术解决了XX问题。
具体而言，该方法首先XX，然后XX，最终实现了XX的效果。
实验结果表明，该方法在XX数据集上达到了XX%的准确率，
相比传统方法提升了XX%。
```

### 方法4: 补充文献标识信息

**DOI 格式**：
```bibtex
@article{key,
  author = {...},
  title = {...},
  doi = {10.XXXX/XXXXX},
  url = {https://doi.org/10.XXXX/XXXXX}
}
```

**arXiv 格式**：
```bibtex
@article{key,
  author = {...},
  title = {...},
  journal = {arXiv preprint arXiv:XXXX.XXXXX},
  url = {https://arxiv.org/abs/XXXX.XXXXX}
}
```

## 核心原则

### ✅ 必须遵守

1. **亲自分析**：由主代理亲自分析扩充位置，撰写扩充内容并编织进稿件
2. **维持框架**：不删除当前框架下的子标题，不轻易增加新标题
3. **质量优先**：扩充内容必须与原文逻辑连贯，无矛盾
4. **服务论点**：扩展内容必须服务于 writer 定义的核心论点
5. **学术严谨**：避免重复内容，保持论述一致性
6. **文献支撑**：每个扩充点必须有文献支撑，禁止编造
7. **批判性分析（强制）**：每个扩充方向必须同时写出局限性分析和适用边界

### ❌ 禁止行为

1. 不通过子代理完成扩展工作
2. 不删除现有章节结构
3. 不添加与主题无关的"填充内容"
4. 不引入未经核实的信息
5. 不破坏论文的整体逻辑连贯性
6. 不编造虚假文献或数据
7. **不只写优势不写局限**

## 扩展优先级

| 优先级 | 章节类型 | 扩展策略 | 原因 |
|--------|----------|----------|------|
| 1 | 与核心论点强相关的章节 | 深度阐述 + 案例分析 | 支撑核心贡献 |
| 2 | 方法论章节 | 框架图 + 伪代码 + 技术细节 | 增强可复现性 |
| 3 | 实验/对比章节 | 对比表 + 结果分析 | 增强说服力 |
| 4 | 结论和展望章节 | 适度扩展未来方向 | 避免过度扩展 |
| 5 | 背景介绍章节 | 谨慎扩展，避免重复 | 易与前文重复 |
| 6 | 方法论章节 | **局限性补充（策略5，强制）** | 确保批判性分析完整 |

## 失败案例规避

### ❌ 案例1: 空洞扩展

**现象**: 扩充内容虽然字数达标，但缺乏实质内容，全是套话。

**根因**: 未基于文献扩充，仅靠"水字数"。

**规避**: 
- 每个扩充点必须有文献支撑
- 扩充内容必须包含具体技术细节或案例分析
- 避免使用"众所周知"、"显然"等空洞表述

### ❌ 案例2: 破坏框架

**现象**: 为扩充内容增加过多新子标题，导致框架臃肿。

**根因**: 未遵守"不增加新标题"原则。

**规避**:
- 严格在现有框架下扩充
- 内容扩充优先于结构调整
- 如需调整结构，应与作者协商

### ❌ 案例3: 图表与正文脱节

**现象**: 增加的图表与正文论述不一致，或图注过于简单。

**根因**: 图表设计未与正文内容同步。

**规避**:
- 图表设计前仔细阅读相关章节
- 图注必须说明图表在文中的作用
- 正文必须引用并讨论图表内容

### ❌ 案例4: 引用不规范

**现象**: 扩充内容引用格式错误，或出现 `[??]`。

**根因**: 未正确添加交叉引用。

**规避**:
- 使用 `\cite{key}` 格式
- 确保参考文献列表包含所有引用
- 编译后检查无 `[??]`

## 最佳实践

### 1. 先诊断后扩展

不要急于扩展，先全面分析初稿，制定扩展计划。

### 2. 深度优先于广度

优先深度阐述现有内容，而非增加新主题。

### 3. 图表服务于内容

增加的图表必须帮助理解正文，而非单纯凑页数。

### 4. 保持风格一致

扩展内容的语言风格、术语使用必须与原文一致。

### 5. 迭代优化

扩展后通读全文，进行多轮优化调整。
